asdf islamorada quickstart 
step 0: be logged in to islamorada.sese.asu.edu
These instructions are for running asdf on islamorada.sese.asu.edu. Everything 
here is intended to be run from the command line while logged in to islamorada. 
They will definitely not work as a way to set up asdf on your personal computer,
and they will not work reliably while logged in to other sese.asu.edu servers 
(such as barbados). If you’re not sure if you’re logged in to islamorada, check 
to see if ‘islamorada’ is in your terminal prompt, or run:
uname -a
If you’re having trouble logging in to islamorada or general trouble with the 
environment that doesn’t appear to be related to asdf, please contact the system
administrator, Nathan Cluff, at nacluff@asu.edu.


section I: setup
________________
IMPORTANT: you only need to perform this setup procedure once. After that, your 
shell will be ready to use asdf as described in section II, unless you delete or
modify your shell configuration files.
step 1: detect your shell
Depending on your sese.asu.edu account’s history, your login shell may be either
tcsh or bash. To find out what your default shell is, run:
echo $SHELL
If this says /bin/bash, your default shell is bash. If it says /bin/tcsh, your 
default shell is tcsh. In the instructions below, this is $YOUR_SHELL.
$YOUR_SHELL_CONFIG  is .bashrc if $YOUR_SHELL is bash, and .tcshrc if 
$YOUR_SHELL is tcsh.
step 2: configure conda 
asdf uses a program called conda[1] to keep its software environment in order. 
You need to tell your shell where conda is and how to use it in order to run 
asdf. 
Start by running:
nano ~/$YOUR_SHELL_CONFIG
At the top of this file, add this line:
export PATH="/opt/miniconda3/bin:$PATH"
Press ctrl+O to save, then ctrl+X to exit. Now close and reopen your shell.
Now run:
mkdir -p ~/.conda/envs/
ln -s /scratch/asdf/vendor/conda/asdf ~/.conda/envs/asdf
conda init $YOUR_SHELL
This command should spit out a bunch of output, which should look something like
this:
no change /opt/miniconda3/condabin/conda 
no change /opt/miniconda3/bin/conda 
no change /opt/miniconda3/bin/conda-env 
no change /opt/miniconda3/bin/activate 
no change /opt/miniconda3/bin/deactivate 
no change /opt/miniconda3/etc/profile.d/conda.sh 
no change /opt/miniconda3/etc/fish/conf.d/conda.fish 
no change /opt/miniconda3/shell/condabin/Conda.psm1 
no change /opt/miniconda3/shell/condabin/conda-hook.ps1 
no change /opt/miniconda3/lib/python3.9/site-packages/xontrib/conda.xsh 
no change /opt/miniconda3/etc/profile.d/conda.csh 
modified /home/$YOUR_USERNAME/$YOUR_SHELL_CONFIG
==> For changes to take effect, close and re-open your current shell. <==
You can ignore all of this output (you’ll close and reopen your shell again in a
moment).
Step 3: configure your shell
Open your shell configuration file again:
nano ~/$YOUR_SHELL_CONFIG
Now scroll down to the bottom of this file (using the Down Arrow key) and add 
the lines:
conda activate asdf
alias asdf "python asdf.py"
Again, press ctrl+O to save, then ctrl+X to exit; then close and reopen your 
shell. In front of your shell prompt, you should now see (asdf).
section II: using asdf
________________
IMPORTANT: You should always run asdf from the /scratch/asdf directory, and you 
should always run it while logged in to islamorada.sese.asu.edu (not barbados or
any other sese.asu.edu server). To get to the asdf directory, run:
cd /scratch/asdf
basic asdf usage
To run asdf on a set of IOF files, producing rapidlooks, context images, a ROI 
FITS file, and data/metadata .csv files, run:
asdf $path_to_image $optional_roi_file
asdf will automatically detect the other image files from an observation if they
are in the same directory or elsewhere in its search path. You can also pass it 
the path to a directory instead of a specific image file, and it will show you 
all the observations in that directory and allow you to choose one (or all). By 
default, it hides thumbnails and images from broadband-only observations.
The ROI file can be a MERspect .sel file or a -roi.fits file, generated by asdf 
or otherwise (a FITS file containing one 2D array per ROI, valued 1 within that 
ROI and 0 elsewhere).
If you don’t pass it a ROI file, asdf simply generates rapidlooks and  .csv 
files containing only metadata.
The default directory for all of asdf’s output is 
/scratch/asdf/output/$YOUR_USERNAME/$OBSERVATION_SOL .
other important asdf options
-a, --abbreviated: pass abbreviated path names for image files. The syntax is:
asdf -a $SOL,$SEQ_ID,$TREE,$SUBDIRECTORY
Example:
asdf -a 82,,proj
This command finds all multispectral observations in 
/project/m2020/mastcamz/surface/flight/products/0082/iof/ . Using 
asdf -a 82,03131,proj
would instead show observations only with sequence id zcam03131.
$TREE is one of either "scratch" or "proj". It is optional and defaults to 
"scratch". $SUBDIRECTORY is any subdirectory name (like "iof," "iof_est", etc.).
It is optional and defaults to "iof". Note that $SEQ_ID is optional, but a comma
must be present.
--upload: upload thumbnails, metadata, and data/metadata backups.
-s, --suffix: add a suffix for a specific “analysis.” Useful if you have 
multiple ROI files for an observation. This distinguishes analyses generated 
from different ROI files in both filenames and metadata.
For a complete list of options, run asdf --help.
full example of usage
asdf /scratch/cal_wg/flight/products/0036/iof/ZL5_0036_0670134129_053IOF_N003139
2ZCAM03107_1100LUC01.IMG examples/asdf.sel --upload
This command:
*  runs asdf on the specific group of IOFs in the 
/scratch/cal_wg/flight/products/0036/iof/ directory that contains 
ZL5_0036_0670134129_053IOF_N0031392ZCAM03107_1100LUC01.IMG
* evaluates examples/asdf.sel on those IOFs
* writes rapidlooks, data, and metadata out to 
/scratch/asdf/output/$YOUR_USERNAME/0036/
* uploads thumbnails, metadata, and backup data
* updates the Google Sheet
